# life_home

Workspace for the **XREAL-Controlled Stretch 3** project — head-tracking
teleoperation of a Hello Robot Stretch 3 using XREAL One Pro AR glasses.

This repository is the umbrella that glues the moving parts together:
the open-source XR Linux driver, the head-control application, the
ROS 2 workspace synced to the robot, and the project documentation.

---

## Repository layout

```
life_home/
├── docs/
│   ├── rendered/         Polished, titled PDFs ready to read
│   └── references/       Third-party / no-source reference material
│   (docs/sources/ exists locally with .tex/.html/.md inputs;
│    it is gitignored — see "Regenerating documents" below)
├── scripts/              Helper scripts that generate documentation
├── data/                 Datasets / trackers (e.g. progress_tracker.csv)
├── shared_folder_btw_stretch3_mypc/
│                         Local mirror of the robot's ~/het_ros2_ws
│                         (synced over SFTP — see .vscode/sftp.json)
├── XRLinuxDriver/        Submodule: third-party wheaney/XRLinuxDriver
└── xreal_head_control/   The head-control app (currently a separate
                          repo — see "Converting xreal_head_control to
                          a submodule" below)
```

## Cloning (for collaborators)

```bash
git clone --recurse-submodules <this-repo-url> life_home
cd life_home
```

If you already cloned without `--recurse-submodules`:

```bash
git submodule update --init --recursive
```

You will also need to clone the head-control app separately until it
is converted to a submodule:

```bash
git clone https://github.com/het915/stretch_gazebot.git xreal_head_control
```

## Reproducing the project

1. Build the XR Linux driver (`XRLinuxDriver/`) — see its own
   `README.md`. Provides AR-glasses IMU access on Linux.
2. Run the head-control app from `xreal_head_control/` — follow its
   `HOW_TO_USE.txt`.
3. Mount the robot's ROS 2 workspace at
   `shared_folder_btw_stretch3_mypc/het_ros2_ws/` over SFTP using
   `.vscode/sftp.json` (set the password locally; it is **not**
   stored in this repo).

## Regenerating documents

Document **sources** live in `docs/sources/` on your local working
copy but are **not committed** (they are gitignored). The committed,
shareable artifacts are the rendered PDFs in `docs/rendered/` and the
reference material in `docs/references/`.

If you have the sources locally:

- **LaTeX**: `cd docs/sources/latex && latexmk -pdf project_proposal.tex`
- **HTML → PDF**: open the files in `docs/sources/html/` in a browser
  and print to PDF (the originals were generated by Chrome/Chromium
  print).

## Converting `xreal_head_control` to a submodule

The folder is currently a **separate clone** of
`https://github.com/het915/stretch_gazebot.git` and is gitignored
because it contained uncommitted local changes at the time of the
initial restructure.

When you are ready to convert it:

```bash
# 1) Push your local changes to GitHub from inside the folder
cd xreal_head_control
git status                 # confirm what is local
git add -A && git commit   # if you want everything captured
git push origin master

# 2) Replace the folder with a real submodule
cd ..
mv xreal_head_control xreal_head_control.bak
git submodule add https://github.com/het915/stretch_gazebot.git xreal_head_control
git -C xreal_head_control checkout <commit-you-just-pushed>

# 3) Restore any uncommitted-but-needed files from the backup
#    (rsync everything except the .git folder)
rsync -a --exclude=.git xreal_head_control.bak/ xreal_head_control/
rm -rf xreal_head_control.bak

# 4) Drop the gitignore entry for the folder, commit
sed -i '/^xreal_head_control\/$/d' .gitignore
git add .gitmodules xreal_head_control .gitignore
git commit -m "Convert xreal_head_control to submodule"
```

> ⚠️ Security note: at the time of this restructure,
> `xreal_head_control/HOW_TO_USE.txt` contained a plaintext SSH
> password and the robot's IP. Strip those before pushing anywhere
> public.

## Secrets

`.vscode/sftp.json` is committed with a placeholder password. Set
your real password locally; **never commit it**. The robot login is
not stored in this repo.

The `.gitignore` blocks `*.pem`, `*.key`, `.env*`, and `secrets/`
directories repo-wide.
